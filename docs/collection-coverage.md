# 采集范围与完整性

本轮继续补齐采集范围，仍不依赖分析模型。实际完成数量见用户页面“查看各渠道本轮采集范围”，以及目录 `price_update.sources`。

最新一轮核验 **9,788 条有效报价**；用户下拉列表按明确别名归一后列出 **8575 个对象**。OnlineSIM 完成 98/98 个国家（2,556 条报价），SMSPVA 完成 69/69 个国家（349 条报价）。SMS4Sats 全目录 802 项中，本轮完成询价 301 项，274 项有价、27 项暂无库存，501 项仍未完成；其余缺口没有伪装成已完成。

## 新的采集范围

- **OnlineSIM**：读取官方国家目录，只扫描启用的国家；按国家读取全部分页。核对响应国家与请求国家，防止接口忽略参数后把默认国家价格错误套到其它国家。单国最多 20 页，未完整读取的国家不发布新价格。
- **SMSPVA**：读取官网 `allServices` 和 `allCountries` 的完整 JSON 字面量，不执行网页脚本。对各国家分别读取访客价格和库存，只匹配相同服务代码、国家及运营商，不使用首页国家宣传最低价。
- **SMS4Sats**：全目录对象逐项调用官方只读 quote；不再只询价四个重点对象。`price_targets` 只决定询价优先顺序。HTTP 409 或明确无库存算已检查但无可用报价，不创造订单、发票或号码预约。

这三个批量流程每个来源最多 3 个并发请求，单来源最多 6 分钟；任务总网络预算仍为 25 分钟。SMSAK 的大响应仍单独使用 HTTP 6 分钟、流程 7 分钟。

为了控制目录体积，OnlineSIM 和 SMSPVA 对全部有库存对象保存所采集国家中的渠道最低公开价，对 `price_targets`（以及「其他/未列出 (Any Other)」回退对象）额外保存逐国最低价。最低价证据保留实际国家和运营商，不代表相同号码类型或最终锁价。不同币种不换算，SMS4Sats 保留 sats。

SMS4Sats 保存各服务代码的询价尝试时间；除重点对象优先外，优先询价未尝试或较旧的项目，不会每轮固定重复目录开头。单个询价最多 15 秒，失败仍记为未完成；从旧版本升级时也会从现有报价证据恢复进度。

部分国家或对象超时、限流、响应不完整时，会保留完整取得的其它结果，并明确写出完成数及缺失原因；没有重新取得的历史价格保留并标记。不会把部分成功宣称为全量完成。

已知国家同义写法（如 Britain / Unt. Kingdom / GB）统一供筛选，保留虚拟号路由区别。已维护的对象别名优先于旧重复名称，Google/YouTube/Gmail 同组写法不会被旧记录拆开，Google Voice 等独立产品仍保留。

## 怎样查看完整性

用户页面新增来源采集表，逐个渠道展示：

| 字段 | 含义 |
|---|---|
| 已拉取对象 | 本轮得到有效来源记录的不同接码对象数 |
| 本轮有价对象 | 本轮得到有效报价的不同对象数，避免把同一对象多个国家的报价误算成多个对象 |
| 报价条数 | 保留的最低价及重点对象国家报价数量 |
| 逐国完成 | OnlineSIM/SMSPVA 完整读取的国家数 / 目录中计划读取的国家数；其它接口未逐国扫描时明确显示未统计 |

这些数只反映本轮，不把保留的旧数据算成新结果。无报价可能是无库存、未公开或未采集；仅凭目录存在不能推断已拿到价格。

## 仍需补齐

- SMS-Man、Tiger SMS、GrizzlySMS 的独立平台密钥目前尚未填写，不能完成真实认证接口联调。文件为 `config/provider-keys.json`，还需填写实际原币种。
- Textverified 已取得完整公开对象列表，详情价格目前按 `price_targets` 拉取；没有把数千个对象都标成有价。
- HeroSMS 和 GrizzlySMS 的匿名首页只提供当前公开展示的对象/卡片，不代表全部后台目录。
- 部分来源有 403、网络差异，或没有公开的稳定对象目录。共享号码页上的短信发送者和验证码内容不能作为对象/价格来源。
- 租赁价格、不同号池和完整规则仍有缺失；单次接码 API 的价格不会套用给租赁产品。

新增测试覆盖有界并发、取消后不再请求、跨国最低价、错误国家响应、库存过滤、部分失败保留有效国家、页面元数据重复键拒绝、非重点对象询价和来源统计。真实账户交易、收码和移动端性能仍未实测。
