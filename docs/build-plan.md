当前目录已清理不可用站点，保留 24 个主渠道、3 个候选；本文原数量为历史资料，以 [最新复核记录](site-availability.md) 为准。

最新补充：用户已要求单独管理员面板，可填写自己的邀请链接并应用到导航购买入口。具体路径、契约、安全边界、生成链路和新对话实施步骤以 [HANDOFF.md](../HANDOFF.md) 为准；本文件早期“不做在线后台编辑”和“排除推广参数”的描述，仅适用于未授权第三方推广，不排除这次明确授权的独立管理项目。

## 产品范围

用户在本站筛选、比较信息，选择后跳转对应平台官网，自行注册、充值、购买、收码、退款或续费。本站仅展示平台及号码产品信息，不处理真实号码订单，不接收短信，不保存购买账户或支付凭据。

这里的“号码”是待购买的号码产品/套餐，展示的是官方承诺的可用时长和复用条件。本站不知道用户实际购买时间与到期时间，因此不显示个人剩余倒计时，也不声称锁定了某个实际号码。

## 栏目

保留免费区与付费区两个主区。付费区分为“一次性号码”和“续费号码”；两个栏目都可按未收码可退、不可退、规则待核实筛选，避免长租混入一次性价格榜。

| 栏目 | 展示内容 |
| --- | --- |
| 免费区 | 免费公共号码来源、在线时长说明、复用是否保证、公开收件箱提示、前往官网 |
| 付费／一次性号码 | 分钟级或单次产品；未收码可退款／不可退款／待核实；官方报价、时长、复用条件 |
| 付费／续费号码 | 按小时/天/周/月租赁的产品，包含 1 天、7 天、30 天等；保留“续费支持／不支持／有条件／未知”标签 |

按用户命名，日/周/月租统一放“续费号码”栏，但栏目归属不代表所有套餐一定支持续费。1 天定期租赁即使明确不可续，也放该栏并标记“不可续费”。12 小时等租赁也归该栏；不能仅按是否超过 24 小时来判断。

1 天、7 天、30 天是快捷筛选，不给每个平台凭空补齐套餐。1 周可按明确的 7 天处理；“1 个月”保留原单位，未确认固定天数时不能冒充“30 天”。未知租期不进入指定租期筛选。

只有平台级资料、产品类型未确认的入口显示在“产品资料待核实”列表，仍可查看官网，不强行归入一次性或续费号码；不因数量不多而虚构套餐。待核验候选与已收录入口分开计数。同一家平台不同域名/别名去重；E码云/D1 等疑似相关入口只记录已核实关系，不能宣称独立资源池。

## 必须显示的号码标签

| 标签 | 取值与含义 |
| --- | --- |
| 可用时长 | 如 20 分钟、5–30 分钟、24 小时、7 天、30 天、1 个月、未知；说明从购买/首次激活等哪个时点起算，未核实则明确未知 |
| 期限内再次收码 | 支持／不支持／视套餐／未知；注明同一服务还是多服务、次数限制、额外费用 |
| 结束后再次使用同号 | 不支持／库存允许时可再次激活／支持保留／未知；不能把“期限内再收一条”写成“以后随时可用” |
| 保留同号续费 | 支持／不支持／有条件／未知；续费必须保留原号码，重新购买随机号不算续费 |
| 自动续费 | 支持／不支持／未知；只展示官方能力，实际开关在官网操作 |
| 续费窗口与价格 | 最早/最晚续费时间、按当前价还是固定价、是否有最低时长和额外费用；未确认不编造 |
| 到期后恢复原号 | 不可恢复／技术条件允许／人工申请／未知，说明可能丢号；与到期前续费分开 |
| 在线方式 | 持续在线／需要唤醒／未知；保留 30 天不意味着随时能立刻收到短信 |
| 退款规则 | 未收码可退／不可退／有条件／未知，注明退余额或原路、取消窗口及产品适用范围 |
| 资料来源 | 官方产品页、价格页、规则来源和核验时间；冲突时保留“资料冲突待核实” |

卡片示例（字段示意，不是真实报价）：平台 A · 7 天租赁 · USD X/7 天 · 期限内可再次收码 · 同号续费有条件 · 到期恢复不保证 · 官网购买。

## 价格与排序

1. 按相同国家、服务、号码类型、期限、服务范围及计费单位比较；一次性与租赁分榜，免费与付费分榜。
2. 默认使用官方公开价格，不需要用户提交 API Key。官网必须登录才显示价格时，标“登录官网查看价格”，不把空值设为 0。后续仅在获得许可且确有需要时增加服务端只读报价 API。
3. 区分“具体产品报价”“官网宣传起价”“需登录报价”“未知”。宣传起价可以作为低价入口展示，不能混入同条件精确价格排序。
4. 记录原价、币种、单位、对应国家/服务、是否促销、来源、核验时间和费用限制。赠金或首次优惠不当作永久免费；外链广告价格不当作来源站自营价格。
5. 同币种、同期限按精确十进制金额排序；显示值四舍五入后不改变底层顺序。跨币种只有在明确同一汇率快照时折算，否则分组；sats 不直接和美元数字比较。
6. 续费号码默认比较同租期总价，可辅助显示日均价；不以 1 天价乘 30 伪造实际月包价格。首购价和续费价分别记录。
7. 人工核验的价格明确显示“核验于”，不标“实时”。建议人工资料超过 7 天提示待更新，这是工程刷新策略，不是价格保证。若之后增加官方自动报价，按源站允许频率缓存，并显示最近成功时间。
8. 最终价格、可用库存和退款资格在官网确认。外链本身不因报价未知而失效；平台无法访问或域名归属待核实则显示异常状态。

## 跳转行为

- 按钮统一为“前往官网购买”“前往官网续费”或“查看免费号码”，清楚显示目标平台和域名。
- 优先链接到已验证的对应服务/租赁页；只确认首页时跳首页，并提示需要在官网重新选择服务、国家和租期。不能猜测深链参数，不能承诺官网已带入筛选项。
- 链接使用 HTTPS 和固定官方域名白名单；新窗口使用安全的 rel 属性。允许管理员明确填写并校验的邀请链接，排除其他未授权推广，不自动跟随未知跳转地址；邀请覆盖和重新生成规则见交接文档。
- 不传用户账号、验证码、Key 或付款信息。本站不自动触发购买、付款、取消或续费。
- 官方页有相互矛盾的时长/续费说明时，展示冲突并指向官网，不挑一个方便的值写成保证。

## 最小实现

第一版用 **Go 标准库构建工具 + 静态 HTML/CSS + 少量原生 JavaScript**。Go 负责读取目录、校验数据、精确价格比较和生成完整页面，完成后退出；产物可交给已有静态托管或 Web 服务器，线上没有本项目的常驻业务进程。目录只含公开资料，无需数据库、登录、订单状态机、付费 API Key、后台收码任务或充值钱包。沿用原生链接完成跳转。

产品数据最小字段：平台 ID、产品 ID、免费/单次/租赁类型、目标官网 URL、国家/服务范围、时长值与单位/起算条件、期限内复用、结束后复用、同号续费、自动续费、恢复条件、在线方式、退款分类、报价种类/原价/币种/单位、来源和核验日期。未知值显式记录，不用 false 代替未知。

同平台多个产品分开记录，不能用一个平台级“可退/可续”布尔值覆盖所有套餐。API 可用性只作资料字段，不是收录门槛。模板和实际数据分离，以便继续增加平台。

## 数据组织与价格正确性

初期仅用 `data/catalog.json` 一个事实文件，内部包含 providers、products、offers 三组记录；这样既能复用平台资料，也不会让平台级能力覆盖产品差异。不另建仓库、数据库或远程配置服务。

- Provider：稳定 ID、名称/别名、官方域名白名单和官网入口。
- Product：稳定 ID、所属平台、一次性/租赁/免费类型、时长及起算点、复用/续费/恢复条件、退款分类、产品官方入口。每个可核验事实带来源与核验日期，未知/冲突显式记录。
- Offer：所属产品、准确国家、服务、号码类型、租期、总价、币种、计费单位、起价/精确价种类、查询时间与来源；续费价单独字段。涉及不同价格/规则的套餐拆成不同记录。

平台“覆盖多个国家/服务”的列表只用于能力介绍，不能自动展开成多个相同报价。全站起价放单独的起价区；服务或国家未知的起价不进入指定服务/国家精确价格榜。范围租期也不能生成虚构的 1/7/30 天在售套餐。

金额以十进制字符串保存。Go 校验格式、非负值、长度和精度上限，再用标准库 `math/big.Rat` 进行精确比较；不使用 float64。只有同币种、同单位、同服务/国家/号码类型/租期/服务范围的报价属于同一可比组。

构建时按可比组预先生成价格顺序/组内排序序号；浏览器过滤不会改变该组内相对顺序，无需再写一套小数运算。未选齐可比维度时展示分组、起价与未知价，不能生成跨组全局“最便宜”排名。平台名称排序可以用稳定 ID 打破同价平局。

租期用值+原单位表示；月与天保持区别。`supported / unsupported / conditional / unknown / conflicting` 用于复用、续费等事实，不用空字符串和 false 混淆未知。规则与报价各自保留核验时间，页面重新构建不更新事实核验时间。

## 页面与构建流水线

```text
data/catalog.json
        │ 校验 ID、关联、报价维度、官方 URL、事实来源和未知状态
        ▼
Go 构建工具：精确排序 + html/template 安全渲染
        ▼
dist/index.html + styles.css + app.js
        ▼
静态托管 → 浏览器筛选 → 对应平台官网
```

建议初期目录保持简单：`cmd/sitegen/main.go`、`data/catalog.json`、`web/index.gohtml`、`web/styles.css`、`web/app.js`、`go.mod` 和必要测试；逻辑变大后按实际职责拆文件。此处是计划，不表示文件已实现。

生成 HTML 必须包含完整可读目录与官网链接，不依赖客户端首次请求 API 才出现内容。JavaScript 使用原生表单控件和 DOM，负责筛选、隐藏不匹配记录、结果计数与 URL 参数恢复；搜索平台名称和已维护别名，不引入全文搜索引擎、拼音词库或前端路由库。

URL 可表达主区、一次性/续费栏、国家、服务、租期、退款条件与关键词。浏览器前进/后退正确恢复筛选；移动端使用单列卡片或可横向滚动的比较表；标签始终带文字。初版不做收藏同步、在线后台编辑、PWA 或自动交易跳转。

模板启用 `html/template` 上下文转义，不把公开来源内容转成可信 HTML。JSON 严格解码并检查重复/未知字段、唯一 ID、关联和 HTTPS 主机；模板与前端都只接受预先核验的官网链接。未知域名跳转留待人工确认，不用通用重定向接口。允许浏览器缩放，控件有可见标签和焦点状态。

### 面板复核后确定的信息布局

页面先显示免费/付费主区和当前结果计数；付费内提供一次性/续费栏目。筛选区保留关键词、国家、服务、租期、退款条件，附可独立取消的已选条件与“清空筛选”。国家变更时保留仍有效的服务选择，只清除已失效选项并说明原因；切换租期无匹配时不擅自改选其他租期。

桌面以便于横向比较的紧凑行列为主，手机显示单列产品卡片。默认内容按阅读顺序为：平台/产品与国家服务 → 原价和计费单位/报价种类 → 可用时长 → 再次收码与同号续费 → 未收码退款结论 → 核验时间 → 官网按钮。产品代码等实现细节留在资料详情，主页面不使用上游内部代码代替服务名。

退款的关键限制、不可续费和未知结论必须可见；补充条款与来源放原生 `details/summary`，可键盘展开，不用只支持悬停的 tooltip。卡片不做整块自动跳转，主官网链接、规则详情、证据链接各自可操作；用户可以选中复制说明文字。

首屏统计只报告入口数、匹配产品/报价数及资料时间，不显示本站无法观测的余额、个人订单、实际剩余时间或供应商成功率。公开来源价格未知时仍有明确官网入口，不以“价格加载中”无限占位。

### 来源状态与失败呈现

将“没有匹配产品”“官网价格需登录”“未公开价格”“上次更新失败”“资料过期”“规则相互冲突”分开说明。有明确时间的历史库存可展示，但不能标实时；未知库存不得显示成 0，无库存也不等于官网故障。站点自身可访问不能证明供应商可以收码。

目录保留全部供应商报价；只在页面可比组内决定价格顺序，不在采集/目录合并时丢掉非最低报价。统一服务 ID 由维护者显式映射，供应商本地代码只保留来源关系；不按同名、代码或名称包含 hz 等子串自动合并。

每个用户可见承诺都要有相应官方产品依据。第三方 SDK 声明可 reuse、cancel 或支持 handler API，不能推出同号永久复用、退款到账或当前价格可用；一个本地状态复位方法更不代表上游能力。人工核验、官方文档确认、源码线索和未核实事实明确区分。

构建先校验再输出到临时目录，成功后才替换正式产物；部署使用托管方完整发布/回滚机制，失败保留上一版。数据变更可在 Git 中审阅，代码/资料测试通过后生成产物；发布不是本轮动作。不需要用 Docker 才能运行或构建。

## 性能目标与测量

优先减少在线工作：不为每个用户访问重新获取 25 个平台入口的价格，不加载第三方字体、整包图标库和分析脚本。默认用平台文字/简洁占位图标，确需图片时本地小图并按需加载。

第一版预算目标：自有 CSS 与 JavaScript 各不超过 20 KiB 未压缩；当前 25 个平台入口目录的首屏 HTML/CSS/JS 合计压缩传输争取不超过 150 KiB。它们是待验证目标，不是已经测得的数据；未来报价明细增多后重新测量，避免为了预算丢失必要规则。

验收时记录：同一台设备的 Go 构建耗时/峰值 RSS、产物大小；桌面与移动浏览器的首屏传输/渲染、筛选响应；使用当前目录和 1,000 条合成产品记录检查增长趋势。不要拿构建工具内存、静态托管进程内存和用户浏览器内存混为一项，也不拿 Flare 的性能数字当本站测量结果。

Go 的标准库已足够，第一版不引入 Fiber/Gin、Rust WASM、React/Vue、Node/Python 服务、Redis 或 SQLite。若后续确需在线只读价格更新，先增加独立 Go 更新命令并重新生成静态快照；只有明确需要请求时动态处理，才考虑常驻服务。网络更新设置超时、响应大小和有限并发，遵守官方限制，不执行购买接口。

## 实施顺序与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1：资料整理（已完成规划） | 25 个主入口、5 个待核验；时长/复用矩阵、实际供应商清单、公开面板与源码依据、Go 技术取舍 | 官方来源可追溯；交易方案已替换；未知和冲突没有写成支持 |
| 1.5：数据落地（待实现） | 将调研结果转为 catalog.json，Go 校验与静态生成 | 25 个入口 ID 唯一；每条产品和报价字段有依据；未知值不补成支持；候选不计作已核验；校验失败不覆盖产物 |
| 2：导航页面 | 免费／付费一次性／付费续费号码；标签、搜索、国家/服务/租期筛选、官网跳转 | 1/7/30 天租赁进入续费栏；不支持续费的租赁仍明确标记；手机与键盘可操作 |
